# V2 전자결재 연결

V2의 개인 업무와 전자결재는 같은 웍스 화면 안에서 사용한다. 상단 주 메뉴는 ‘내 업무’, ‘기능별 업무’, ‘이메일’, ‘공지사항’ 네 항목이다. 오른쪽 PersonalMenu는 제거하고 개인 화면의 왼쪽에 문서함을 배치한다. `/v2#personal/전자결재`와 `/v2#approval/<view>`로 결재 화면을 다시 열 수 있다.

‘기능별 업무’는 기존 목적지를 DS, OS, SS, PM으로 묶는다. DS는 기존 OS의 A·DS 화면, OS는 DM·소식지 배송과 OP·전화 영업, SS는 셋팅·서비스·CA, PM은 기획·관리로 이동한다. 실제 역할의 기존 허용 조직 목록에 따라 항목을 표시하며 DO에는 대표 항목도 제공한다. 이 재배치는 새로운 업무 권한을 부여하지 않는다. 조직 기능 화면은 기존 조직별 사이드바를 유지하고 개인 화면은 왼쪽 문서함을 사용한다.

왼쪽 문서함의 실제 버튼은 ‘새 결재 작성’(compose), ‘내 결재’(all), ‘임시저장’(draft), ‘진행 중’(pending), ‘승인 완료’(approved), ‘거절·회수’(cancelled), ‘기록’(history), ‘승인 대기’(inbox), ‘처리한 결재’(processed)다. 계정 설정은 문서함 아래의 설정 버튼에서 열고 임시 DO·직원 표시 전환도 아래로 옮긴다. 이 전환은 기존처럼 표현만 바꾸며 실운영 권한의 근거로 사용하지 않는다.

‘이메일’은 실제 회사 메일을 아직 연결하지 않은 빈 화면이며 연결 전이라는 안내만 제공한다. ‘공지사항’은 기존 공지·일정 화면으로 연결한다.

현재는 공개 테스트 전자결재를 연결한다. Works 로그인은 입구만 확인하며, 결재 작성자는 기존 공유 데모 직원이다. Works 직원 ID별 소유권이나 실운영 DO 승인 권한으로 연결된 것이 아니다. 화면의 공개 테스트·방문자 공유 안내를 유지한다. 실제 비밀번호나 회사 문서를 이 데모에 등록하지 않는다.

`app/v2/electronic-approval/[[...path]]/route.ts`는 고정된 전자결재 Site로만 연결하고 V2 또는 DO 로그인 상태를 확인한다. 요청 출처와 경로를 제한하고 demo_session만 전달하며 cookie Path는 모듈 경로로 제한한다. Works 인증 쿠키는 외부로 전달하지 않는다. 모듈은 원본 DO 프론트엔드를 수정하지 않는다.

임시저장은 문서 목록에서 계속 작성할 수 있고 첨부를 보관한다. 첨부는 최대 5개, 개당 3MB, 합계 15MB이다. 공개 데모 자료의 저장 암호화는 방문자 사이의 공유 열람을 제한하지 않는다.

왼쪽 결재 선택은 같은 출처의 iframe 프록시에 역할 경로와 `view` 질의를 전달한다. inbox·processed는 director, 나머지는 employee를 요청한다. 프록시는 데모 역할과 선택한 문서함·작성 상태를 맞추고 cancelled는 거절·회수, processed는 승인·거절·회수 문서를 묶어 표시한다. 임베드 안에서는 중복 헤더·사이드바·상태 탭을 숨긴다. 이 변환은 프록시 응답에만 적용하며 독립 전자결재 Site의 화면은 바꾸지 않는다.

iframe의 `ccw-approval-view` 메시지로 부모 왼쪽 선택 상태를 맞추고 `ccw-approval-dirty` 메시지로 작성 중 변경을 `data-dirty`에 반영한다. 수신할 때 `event.origin`이 현재 출처인지, `event.source`가 실제 해당 iframe의 contentWindow인지 모두 검사하며 선택값은 허용한 view 목록만 받는다. 작성 중 웍스 메뉴 이동에는 기존 미저장 확인을 사용한다. 모듈에서는 웍스 서비스 워커를 등록하지 않는다. 현재 휴대폰 알림 설정은 독립 전자결재 Site에서 한다.

2026-10-09: 고경화 로그인에서 메뉴 이동·작성 화면 표시를 확인했다. 부모 메뉴로 이동할 때 미저장 확인이 뜨고, 취소 후 작성 내용을 유지했다. 로컬 첨부 업로드·임시저장·이어 작성·다운로드 원본 SHA256 일치 및 백엔드 테스트 6개를 확인했다. 실제 Works 직원별 결재 신원 통합과 실운영 권한 체계는 후속 범위다.

후속 헤더·왼쪽 문서함 수정은 `workspace.tsx`, `organization-nav.tsx`, `approval-navigation.tsx`, `electronic-approval.tsx`와 프록시 route 소스를 읽어 기록했다. 네 항목의 헤더, 기존 조직 목적지와 역할별 표시, 개인·조직 사이드바 구분, 실제 문서함 버튼과 footer 설정·표시 전환, 역할·view 요청과 메시지 검증·동기화를 확인했다. 이번 문서 작업에서는 새 화면 캡처나 런타임 검증을 수행하지 않았으며 위 이전 검증이 이번 메뉴 수정의 시각 검증을 대신하지 않는다. 최종 캡처와 통합 검증은 진행 중이다. 루트 DESIGN, AGENTS와 canonical DO는 변경하지 않는다.

최종 검증: V2 전용 navigation.css를 Workspace에서 직접 불러온다. 자식의 보고 상태와 iframe 요청 상태를 분리해 이어 작성·재상신 중 보고 메시지가 iframe을 다시 불러오지 않도록 했다. 배포 dpl_8xpxKeAu57RjKAGTPpEBZjk1v5eB의 빌드·TypeScript 검사를 통과했다. 실제 배포 화면에서 네 메뉴, 기능별 하위 메뉴, 임시저장 목록, 가운데 결재 작성, 이사님 대기함과 이메일 미연결 안내를 확인했다. 390×844에서 상단 메뉴와 모바일 문서함을 확인하고 viewport를 복원했다. 새 캡처는 new-chat-2/outputs/works-v2-nav/desktop.png 및 mobile.png에 보관했다.

2026-10-09 속도 수정: 문서함 선택 시 iframe 주소를 바꾸지 않고 같은 출처·실제 부모 프레임을 검증한 메시지로 전환한다. 같은 역할의 목록·작성 전환은 외부 API를 다시 호출하지 않는다. 직원/이사님 역할을 바꿀 때에는 기존 데모 역할 전환과 상태 조회를 유지한다. 유효한 기존 세션은 상태부터 읽어 불필요한 demo-start를 생략한다. 공개 화면 파일은 5분 재사용하고 각 배포의 브라우저 파일 주소를 구분한다. 결재·계정 API와 개인 데이터는 no-store를 유지한다. 실제 Chrome 문서함 전환 1회 측정: 수정 전 2187ms, 수정 후 177ms. 초기 외부 연결의 지연은 별도다. scripts/test-approval-navigation.cjs로 출처·대상 검증, 역할별 전환과 같은 역할에서 API 미호출을 확인했다.
